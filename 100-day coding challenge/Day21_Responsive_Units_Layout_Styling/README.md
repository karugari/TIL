## 2. 반응형 디자인의 진짜 의미 
반응형 디자인은 단순히 "화면을 작게 만드는 것"이 아님
장치의 크기나 해상도에 따라 웹사이트의 레이아웃, 콘텐츠 크기, 이미지를 최적의 상태로 조정하는 기술을 의미함

반응형이 필수인이유 
개발자는 유저가 아이폰을 쓰는지, 거대한 모니터를 쓰는지 아니면 반으로 접히는 폴더블 폰을 쓰는지 미리 알 수 없기 떄문
최적의 사용자경험(UX)
화면이 커졌을 때 이미지가 너무 휑하게 늘어나거나, 화면이 작아졌을 떄 메뉴 버튼이 겹쳐서 클릭할 수 없는 상황을 방지해야함
## 3. 픽셀(px)의 한계와 상대 단위의 등장 

### 픽셀($px$)의 한계
#### 1. 확장성(scakability)의 부재
팍셀은 절대 단위(Absolute Unit)임. 화면이 거대한 아이맥이든 작은 스마트폰이든 상관없이 10px은 물리적으로 동일한 크기를 고수함
- 문제: 화면 크기에 따라 디자인의 비율이 유동적으로 변해야 하는 반응형 웹에서는 이'고정된 성질'이 레이아웃을 딱딱하게 만듬
#### 2. 사용자 권리 침해: 브라우저 설정 무시
모든 사용자가 시력이 좋은게 아니기때문에 어떤 사용자들은 브라우저 설정에서 글꼴 크기: 매우크게를 선택해 웹서핑을 함

- 브라우저의 기본값: 보통 16px
- 상대 단위 사용시: 사용자가 설정을 키우면 글자도 같이 커짐. (접근성 확보)
- 픽셀(px) 사용시 개발자가 20px로 고정해버리면, 사용자가 브라우저 설정을 아무리 바꿔도 글자크기는 요지부동임, 이는 특정 사용자들에게 웹사이트 이용을 불가능하게 만드는 결과를 초레함
## $em$과 $rem$
상대 단위 비교표

| **유닛**    | **기준점 (Reference)**    | **특징**                         | **위험 요소**                 |
| --------- | ---------------------- | ------------------------------ | ------------------------- |
| **`\%`**  | **부모 요소**의 폰트 크기       | 직관적이지만 중첩될수록 계산이 복잡함           | 계층이 깊어지면 관리가 힘듦           |
| **$em$**  | **부모(또는 자기 자신)**의 크기   | 현재 맥락에 따라 크기가 변함               | **복리(Compounding)** 효과 발생 |
| **$rem$** | **최상위($html$) 요소**의 크기 | 어디서든 기준이 일정함 (**R**oot **em**) | 모든 크기가 똑같이 변할 수 있음        |
### . $em$과 $rem$의 결정적 차이

이 두 유닛을 정확히 구분하는 것이 반응형 디자인의 핵심

- **$em$ (Element em):** "가족 중심적" 단위입니다. 부모의 폰트 크기가 $20px$일 때 자식에게 $2em$을 주면 $40px$이 됩니다. 하지만 이 자식의 자식에게 다시 $2em$을 주면 $80px$이 되어버리는 **중첩 문제**가 발생합니다.
- **$rem$ (Root em):** "국가 표준" 단위입니다. 부모가 누구든 상관없이 오직 **최상위 요소($html$)**의 크기만을 참조합니다. 브라우저 기본값이 $16px$이라면, $1rem$은 어디서나 $16px$입니다.

사용자가 브라우저 설정에서 "글자 크게"를 선택하면, 최상위($html$)의 기본값이 $16px$에서 $20px$ 등으로 변합니다. 이때 모든 수치를 **$rem$**으로 작성했다면, 사이트의 모든 요소(폰트, 여백, 너비 등)가 사용자의 설정에 맞춰 **비율을 유지하며 동시에 확대**됩니다.

> **TIP:** > 실무에서는 예측 가능한 레이아웃을 위해 **$rem$**을 주력으로 사용하고, 특정 컴포넌트 내부에서만 비율을 유지해야 할 때(예: 버튼 텍스트 크기에 맞춰 패딩이 변해야 할 때) 제한적으로 **$em$**을 섞어서 사용합니다.
