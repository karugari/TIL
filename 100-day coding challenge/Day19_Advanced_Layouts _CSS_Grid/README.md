# Day19_Advanced_Layouts _CSS_Grid

## 1. 카드 룩의 완성 
카드의 핵심 디자인은 왼쪽에는 이미지, 오른쪽에는 설명이 오는 구조 
이를 위해 
부모인 `<li>`에 `display: flex` 선언

**결과**: 플렉스의 기본 방향인 가로(`row`) 정렬에 따라 이미지와 텍스트 박스가 예쁘게 나란히 서게 됩니다.

카드의 `border-radius`를 6px로 줬는데, 왼쪽 이미지가 여전히 직각으로 보였던 이유는 이미지가 부모(`li`)의 테두리 위를 덮고 있었기 때문입니다.
- **현상**: 자식 요소(이미지)가 부모 박스의 경계선을 무시하고 시각적으로 삐져나옴.
- **해결**: 부모 요소에 **`overflow: hidden`**을 적용.
- **효과**: 부모 박스의 차원을 벗어나는 모든 자식 요소의 부분을 보이지 않게 "잘라냅니다(Masking)". 이로써 이미지도 부모의 둥근 모서리에 맞춰 예쁘게 깎이게 됩니다.

### 중첩 플렉스의 묘미: 왜 `<div>`로 묶었을까?

`.item-content` 내부에 `h2`, `p`, `actions` 세 가지 요소가 있을 때 `justify-content: space-between`을 쓰면 세 요소가 균등하게 벌어집니다. 하지만 우리가 원하는 건 **(제목+설명)은 위로, (링크)는 아래로** 보내는 것이었죠.

- **해결책**: `h2`와 `p`를 하나의 `<div>`로 묶어(Wrapper) 플렉스 아이템을 **2개**로 줄임.
    
- **결과**: 플렉스 박스는 (제목/설명 박스)와 (링크 박스) 사이의 공간만 최대화하여 링크를 바닥으로 완벽하게 밀어냄.

### 요소의 우측 정렬: `text-align: right`

`.actions` 컨테이너 자체를 우측으로 보내기 위해 `text-align: right`를 활용했습니다. 이는 링크와 같은 인라인 요소를 부모 박스 안에서 오른쪽 끝으로 정렬하는 가장 간편하고 확실한 방법입니다.

## 2. 레이아웃의 새로운 차원: CSS Grid 
목표한 페이지처럼 카드가 2차원적으로 배치되어야 할 때는 Flexbox만으로는 한계가있다
### 1. 왜 Flexbox로는 부족할까? (1D vs 2D)
Flexbox는 기본적으로 **1차원(1-Dimensional)** 레이아웃 도구
- **Flexbox의 한계**: `flex-wrap`을 쓰면 요소들을 다음 줄로 넘길 수는 있지만, 각 요소가 행과 열을 동시에 가로지르거나 특정 열의 크기를 엄격하게 고정하는 작업을 수행하기에는 매우 복잡하고 불안정합니다.
    
- **Grid의 등장**: CSS Grid는 **2차원(2-Dimensional)** 레이아웃 도구입니다. 가로축(Row)과 세로축(Column)을 동시에 설계할 수 있어, 바둑판 모양이나 신문 레이아웃 같은 복잡한 구조를 훨씬 쉽게 만듭니다.

| **특징**    | **Flexbox**           | **CSS Grid**               |
| --------- | --------------------- | -------------------------- |
| **차원**    | 1차원 (1D) - 행 **또는** 열 | 2차원 (2D) - 행 **과** 열 동시 제어 |
| **주 목적**  | 요소들을 일렬로 정렬 및 공간 배분   | 복잡한 격자 구조 설계 (신문, 카드 룩)    |
| **적용 방식** | 콘텐츠 크기에 따라 유연하게 변함    | 설계자가 정한 레이아웃 틀에 콘텐츠를 맞춤    |
### 그리드 컨테이너의 핵심 속성

부모 요소에 `display: grid;`를 선언
- **`grid-template-columns`**: 열의 개수와 너비를 정의합니다.
    - `400px 400px`: 400픽셀 너비의 열 2개 생성.
    - **`1fr 1fr`**: 사용 가능한 공간을 똑같이 1:1 비율로 나눔.
- **`gap`**: 요소들 사이의 간격을 정합니다. 마진(Margin)의 복잡한 중첩 문제를 해결해 주는 구원투수입니다.
    - `gap: 100px 200px;` (행 간격 100px, 열 간격 200px)

스크립트에서 강조했듯이, Grid에서는 `px`보다 `fr` 단위를 훨씬 선호합니다.

> ** 왜 `fr`인가?** `fr`은 "사용 가능한 공간의 파편(Fraction)"을 의미합니다. `1fr 2fr`이라고 쓰면 전체를 3으로 나눈 뒤 첫 번째 열에 1만큼, 두 번째 열에 2만큼의 공간을 자동으로 할당합니다. 브라우저 창 크기가 변해도 비율이 유지되므로 **반응형 디자인**에 최적입니다.

## 3. 정밀한 선택: `nth-of-type` 

### 1. CSS 저격수: `first-of-type` & `nth-of-type(n)`
특정 순서에 있는 요소를 선택할 때 사용하는 '의사 클래스(Pseudo-class)' 선택자
- **`li:first-of-type`**: 부모 요소 안에서 해당 타입(li) 중 가장 **첫 번째** 요소를 선택합니다.
- **`li:nth-of-type(3)`**: 부모 요소 안에서 해당 타입(li) 중 정확히 **3번째** 요소를 선택합니다.
    - _활용_: 우리 프로젝트에서 3번째 카드(런던)만 가로로 길게 만들고 싶을 때, 별도의 클래스 없이도 이 선택자 하나로 스타일을 지정할 수 있습니다.
### 2. 그리드 라인의 비밀 (Grid Lines)

그리드에서 요소를 배치할 때 가장 헷갈리는 부분이 바로 '숫자 세기'
- **라인 넘버**: 열이 2개라면, 라인은 왼쪽 끝(1), 중간(2), 오른쪽 끝(3) 총 **3개**가 존재합니다.
- **배치 원리**: `grid-column: 시작라인 / 끝라인`
    - `grid-column: 1 / 3;` -> 1번 라인에서 시작해서 3번 라인에서 끝나라. 즉, **2개의 열을 모두 차지하라**는 뜻입니다.
### 3. 유연한 확장: `span` 키워드
라인 번호를 계산하기 번거로울 때 사용하는 더 직관적인 방법
- **`grid-column: 1 / span 2;`**: "1번 라인에서 시작해서 **2칸(span)만큼** 옆으로 가라"는 의미입니다.
- 결과적으로 `1 / 3`과 동일하지만, 레이아웃이 복잡해질수록 몇 칸을 차지할지 명시하는 `span`이 더 읽기 편할 때가 많습니다.
