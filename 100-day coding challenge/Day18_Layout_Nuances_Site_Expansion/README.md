## 1. 레이아웃의 유령: 마진 병합 
섹션 내부 요소에만 마진을 줬는데, 왜 섹션 바깥에 뜬금없는 흰색 공간이 생기는이유 부모-자식 간 마진 병합 현상

- **원인**: 부모 요소에 경계(Border나 Padding)가 없으면, 자식의 마진이 부모의 마진과 하나로 합쳐져 부모 바깥으로 밀려 나갑니다.
- **결과**: 섹션의 배경색이 시작되기도 전에 흰색 여백이 먼저 나타나 레이아웃이 끊겨 보이게 됩니다.
- 해결방법: 경계선(Boundary)만들기
 자식의 마진이 부모 밖으로 탈출하지 못하도록 '벽'을 세워주면 됩니다. 가장 쉽고 흔한 방법은 부모에게 **패딩(Padding)**을 주는 것입니다.

## 2. 코드로 그리는 배경: Linear Gradients
### 1.CSS 함수(Function)란?

CSS함수는 특정 작업을 자동으로 처리하여 결과를 반환하는 도구
- 형태: 함수이름(값1, 값2, ...)
- 특징: `linear-gradient()` 함수는 우리가 입력한 각도와 색상 정보를 바탕으로 이미지 형태의 그라데이션 배경을 생성해 냄
### 2.`linear-gradient` 사용법
단순히 색상 하나를 정하는 것이 아닌 **방향(각도)과 변화할 색상들** 을 정의합니다

```CSS
#highlights { /* 배경 이미지를 생성하는 함수를 사용합니다 */ background: linear-gradient(0deg, rgb(227, 255, 253), rgb(202, 243, 240)); }
```

각도(Angle)에 따른 마법
그라데이션이 흐르는 방향을 조정하여 분위기를 완전히 바꿀 수 있음

| **각도 (deg)** | **방향 설명**     | **시각적 효과**            |
| ------------ | ------------- | --------------------- |
| **`0deg`**   | 아래 → 위        | 가장 안정적이고 깔끔한 수직 그라데이션 |
| **`90deg`**  | 왼쪽 → 오른쪽      | 가로 방향의 색상 변화          |
| **`180deg`** | 위 → 아래        | `0deg`와 반대 방향         |
| **`45deg`**  | 왼쪽 아래 → 오른쪽 위 | 대각선 방향으로 역동적인 느낌 부여   |

## 3. 페이지의 마침표: Footer Section 

footer는 단순히 페이지의 끝이 아니라, 웹사이트의 전체적인 완성도와 신뢰를 주는 영역임

#### 1. 전역 스타일 관리: `shared.css`
헤더와 마찬가지로 푸터 역시 모든 페이지(index, places 등)에서 동일하게 보여야 합니다. 따라서 스타일 코드를 페이지 전용 파일이 아닌 **`shared.css`**에 작성하여 유지보수 효율을 높였습니다.
#### 2. 아이콘 크기 제어의 정석 (Parent-Child)
이미지 자체에 고정 크기를 주는 대신, 부모 요소인 `li`의 크기를 제한하고 이미지가 이를 따라가게 만드는 유연한 방식을 사용했습니다.
- **부모(`li`)**: `width: 80px; height: 80px;`
- **자식(`img`)**: `width: 100%; height: 100%;` (부모가 제공하는 80px 공간을 꽉 채움)
#### 3. Flexbox를 활용한 레이아웃 정렬
- **가로 나열**: `ul`에 `display: flex`를 적용해 세로로 쌓이던 아이콘들을 가로로 정렬했습니다.
- **중앙 배치**: `justify-content: center`를 사용해 아이콘들을 화면 정중앙으로 모았습니다.
- **간격 및 여백**: `li`에 좌우 `margin`을 주어 아이콘 사이의 간격을 벌리고, `footer` 자체에 `padding`을 주어 상하 공간을 확보했습니다.

"푸터 스타일링에서 `justify-content: center`를 사용하는 것은 매우 효과적입니다. 남는 공간을 좌우로 공평하게 배분하여 어떤 해상도에서도 아이콘이 정중앙에 위치하게 만들기 때문

## 4. 확장: 새로운 페이지 준비 

### 1. 효율적인 시작: 복사와 붙여넣기 (DRY 원칙)
웹 개발에는 **DRY(Don't Repeat Yourself)**라는 중요한 원칙이 있습니다. 똑같은 코드를 두 번 쓰지 말라는 뜻

- **공통 요소 추출**: 모든 페이지에서 동일하게 사용하는 `<!DOCTYPE>`, `<head>`, `<header>`, `<footer>`를 `index.html`에서 그대로 가져와 `places.html`에 이식했습니다.
- **연결 확인**: 로고 클릭 시 홈으로, '목적지' 클릭 시 다시 장소 페이지로 연결되는 링크가 올바르게 작동하는지 점검하는 과정이 필수적입니다.

### 2. 스타일의 분리: `places.css`
모든 스타일을 한 파일에 넣으면 관리가 힘들어짐.
- **`shared.css`**: 헤더, 푸터 등 모든 페이지 공통 스타일.
- **`places.css`**: 오직 장소 페이지(Places Page)에서만 사용하는 전용 스타일.
- **HTML 업데이트**: `<head>` 내의 링크를 `styles.css`에서 `places.css`로 교체하여 페이지별 독립된 스타일 체계를 갖췄습니다.
###  3. 현대 웹의 정석: "카드 룩(Card Look)"

이제 `main` 영역에 채워 넣을 디자인 패턴은 바로 **카드 룩**입니다.
- **정의**: 이미지, 제목, 설명, 링크 등을 하나의 독립된 박스(카드)에 담아 나열하는 방식입니다.
- **장점**: 콘텐츠 간의 구분이 명확하고, 모바일과 데스크톱 화면 모두에 대응하기 쉬운 매우 범용적인 디자인입니다.
### 4. 포지션의 '리셋 버튼': `position: static`

모든 HTML 요소의 기본값은 `static`입니다. 하지만 우리는 `shared.css`에서 헤더를 공중에 띄우기 위해 `absolute`를 사용했죠. 랜딩 페이지에서는 멋졌지만, 장소 페이지에서는 헤더가 콘텐츠를 가리는 문제가 생겼습니다.

- **해결 방법**: `places.css`에서 헤더를 다시 **`position: static`**으로 설정합니다.    
- **의미**: "공중에 떴던 헤더를 다시 원래의 문서 흐름(Ground)으로 내려놓겠다"는 뜻입니다. 이렇게 하면 헤더가 다시 블록 요소로서 자기 자리를 차지하게 되고, 아래의 이미지들이 헤더 밑으로 숨지 않게 됩니다.

### 5. CSS의 위계질서: 파일 불러오기 순서

HTML의 `<head>` 섹션에서 CSS 파일을 어떤 순서로 배치하느냐는 레이아웃의 성패를 결정합니다.

- **규칙**: 나중에 선언된 스타일이 이전 스타일을 덮어씁니다.
- **올바른 순서**:
    
    1. `shared.css`: 웹사이트 전체에 적용되는 보편적인 규칙.
        
    2. `places.css`: 해당 페이지에만 적용되는 세부적인 규칙.
        
- **결과**: `places.css`의 `position: static`이 `shared.css`의 `absolute`를 성공적으로 이기게(Override) 됩니다.
