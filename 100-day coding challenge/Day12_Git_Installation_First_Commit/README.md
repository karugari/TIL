# Day 12: Git Core Concepts & First Commit

## 1. Windows 명령 프롬프트 (CMD) 기초
컴퓨터 내부의 계층적 디렉토리 구조를 이해하고, 명령어를 통해 시스템을 제어하는 기초를 학습했습니다.

### 디렉토리 구조
- **Root (루트):** 드라이브 최상위 지점 (`C:\`)
- **Users (사용자):** 모든 사용자 폴더의 집합소.
- **Home (홈):** 현재 로그인한 사용자의 개인 폴더 (`C:\Users\Name`)

### 핵심 탐색 명령어
| 명령어 | 의미 | 설명 |
| :--- | :--- | :--- |
| **`dir`** | Directory | 현재 폴더의 파일 및 하위 폴더 목록 표시 |
| **`cd [명]`** | Change Directory | 특정 폴더로 이동 (Tab키 자동완성 활용) |
| **`cd ..`** | Go Up | 한 단계 상위 폴더로 이동 |
| **`cd /`** | Go to Root | 최상위 루트 디렉토리로 즉시 이동 |
| **`D:`** | Switch Drive | 드라이브 간 전환 (드라이브 명 + 콜론) |
| **`cls`** | Clear Screen | 터미널 화면 깨끗하게 비우기 |

### 절대 경로 vs 상대 경로
- **절대 경로:** 루트(C:)부터 시작하는 고정 주소. 어디서든 정확한 위치 참조 가능.
- **상대 경로:** 현재 위치 기준. 프로젝트 이동 시에도 연결이 깨지지 않아 개발 시 권장됨.

## 2. Git의 핵심 작동 원리: 3가지 영역
Git 프로젝트는 효율적인 버전 관리를 위해 세 가지 논리적 영역으로 나뉩니다.

1. **Working Directory:** 실제 파일을 수정하는 현재 작업 공간.
2. **Staging Area:** 커밋(스냅샷)을 찍기 전, 변경 사항을 선별하여 담는 임시 공간.
3. **Repository (.git):** 버전 기록과 변경 사항(Diff)이 영구적으로 저장되는 숨겨진 공간.

### 커밋과 트래킹
- **Tracking (트래킹):** 파일의 전체 복사본이 아닌 **변경 사항(Diff)**만 추적하여 효율적으로 관리.
- **Commit (커밋):** 특정 시점의 코드 **스냅샷**. 반드시 의미 있는 메시지를 남겨 변경 내역 파악을 용이하게 함.

### 브랜치 (Branch) - 코드의 흐름
- **Main/Master Branch:** 프로젝트의 중심 줄기. 안정적인 코드가 머무는 곳.
- **Feature Branch:** 새로운 기능 개발이나 실험적 작업을 위한 가지치기. 작업 완료 후 Merge(병합) 가능.

## 3. 첫 번째 커밋 만들기

### 사용자 식별 정보 설정 (`git config`)
누가 코드를 수정했는지 기록하기 위한 필수 초기 설정입니다.
- **이름 설정**: `git config --global user.name "Your Name"`
- **이메일 설정**: `git config --global user.email "your@email.com"`

### 저장소 초기화 및 스테이징
1. **저장소 생성**: `git init` (해당 폴더를 Working Directory로 지정)
2. **상태 확인**: `git status` (추적되지 않는 파일 확인)
3. **스테이징**: `git add .` (변경 사항을 장바구니인 Staging Area에 추가)

### 스냅샷 기록 및 이력 확인
- **커밋 실행**: `git commit -m "Commit Message"` (기록 영구 저장)
- **이력 확인**: `git log` (커밋 ID, 작성자, 날짜, 메시지 확인)
