## 1. 유연한 수치 관리: % 단위와 헤더 (L:128 - 129)

### 1. %단위: 부모와의 관계
퍼센트(`%`)단위는 독립적이지 않음 부모요소의 크기를 기준으로 자신의 크기를 결정함
- 동작원리: 부모의 너비가 1000px일 때 자식에게 width: 50%를 주면 500px가 됨
- 유연성: 브라우저 창(부모)이 줄어들면 자식의 너비도 자동으로 비율에 맞춰 줄어드
- 헤더 적용: position: absolute를 주면 문서 흐름에서 빠지면서 너비가 콘텐츠 크기만큼 줄어듬 이때width: 100%를 주어 부모(HTML/Body)의 전체 너비를 차지하게 만듬
### 2. Box-Sizing: 레이아웃이 깨지는 이유
많은 개발자가 width: 100%를 줬는데 가로 스크롤이 생기는 문제의 이유는 브라우저의 기보ㅓㄴ 박스모델 계산 방식 때문

content-box(기본값) vs border-box
브라우저는 기본적으로 우리가 설정한 너비를**순수 콘텐츠 영역**에만 적용함 여기에 패딩이나 테두리를 더하면 전체 박스 크기는 우리가 설정한 너비보다 커지게 됨

|**속성값**|**계산 방식**|**결과**|
|---|---|---|
|**`content-box`**|너비 + 패딩 + 테두리 = 전체 크기|**너비 100% + 패딩 10px = 100% 초과 (스크롤 발생)**|
|**`border-box`**|너비(패딩, 테두리 포함) = 전체 크기|**패딩을 넣어도 전체 너비 100% 유지 (안전)**|

실무에서는 모든 요소에 box-sizing: border-box를 적용하고 시작하는 경우가 많음 그래야 패딩을 추가해도 전체 레이아웃 계산이 꼬이지 않기 때문

### 3. 포지셔닝 복습: 흐름 밖의 세상

`absolute`와 `fixed`는 모두 요소를 공중에 띄우지만, 그들이 '어디를 바라보고 있는가'가 다릅니다.
- **`position: absolute`**: 
    - **기준**: `relative`가 적용된 가장 가까운 조상. 없으면 `<html>`.
    - **행동**: 페이지의 특정 위치에 박제됩니다. 스크롤하면 위로 올라가 사라집니다.
- **`position: fixed`**:
    - **기준**: **뷰포트(Viewport)**, 즉 현재 내 눈에 보이는 브라우저 창 그 자체.
    - **행동**: 스크롤을 아무리 내려도 그 자리에 껌딱지처럼 붙어 있습니다.

### 4. 헤더 레이아웃 완성

- 헤더를 배경 이미지 위에 겹치게 하려면 일반적인'쌓기' 방식에서 벗어나야함
`position:absolute`: 헤더를 문서 흐름에서 제거함 덕분에 뒤에 있던`#hero`섹션(배경이미지)이 헤더 밑으로 올라오게됨
- width:100% & box-sizing:border-box:
	- absolute가 되면 요소의 너비가 콘텐츠 크기만큼 줄어드는데, 이를 다시 화면 전체 너비로 늘려줍니다.
	- 이때 이전에 설정한 60px의 패딩 때문에 화면 밖으로 삐져나가는 현상을 `border-box`설정으로 해결
	- 
헤더가 HTML 구조상 첫 번째 요소라면 굳이 좌표를 적지 않아도 맨 위에 위치합니다. 하지만 **안전한 설계를 위해** `top: 0`, `left: 0`을 명시해 주는 것이 좋습니다. 이는 나중에 다른 요소가 추가되어 문서 흐름이 바뀌더라도 헤더가 항상 제자리에 고정되도록 보장하는 일종의 '보험' 같은 코드입니다.

## 2. 하이라이트 섹션 구축 (L:130 - 133)

### 1. 하이라이트 섹션의 논리적 구조

전체적인 구조는 **제목(`<h2>`) + 리스트(`<ul>`)**로 구성됩니다. 각 여행지 정보는 하나의 리스트 아이템(`<li>`)으로 묶여 관리됩니다.

| **태그**          | **속성**                | **역할**                                       |
| --------------- | --------------------- | -------------------------------------------- |
| **`<section>`** | `id="highlights"`     | 배경색과 전체 레이아웃을 담당하는 큰 틀                       |
| **`<h2>`**      | -                     | 섹션의 제목 ("HIGHLIGHTS")                        |
| **`<ul>`**      | `id="destinations"`   | 여행지 카드들을 담는 컨테이너                             |
| **`<li>`**      | `class="destination"` | 각 여행지 정보를 담는 개별 카드 (반복되는 구조이므로 **Class** 사용) |
### ID vs Class: 왜 이렇게 나눴을까?

이 부분은 사용자님이 나중에 프로젝트를 확장할 때 매우 중요한 개념입니다.
- **ID (`#destinations`)**: 이 페이지에 이 리스트는 **단 하나**뿐입니다. 따라서 고유한 스타일을 적용하기 위해 ID를 씁니다.
- **Class (`.destination`)**: 마이애미, 뮌헨, 바르셀로나 등 **동일한 디자인**을 가진 카드가 여러 개입니다. 이를 한꺼번에 제어하기 위해 클래스를 씁니다.
